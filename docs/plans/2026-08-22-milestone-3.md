# Milestone 3 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Generate a per-user vault, show the recovery phrase once, pair a second device over QR with a 6-digit fingerprint confirm, and prove that device can decrypt an item created on the first.

**Architecture:** VaultKey stays on the client in IndexedDB (non-extractable). A device-local wrapping key holds an extractable copy so pairing can `wrapKey` without keeping extractable material in RAM. Pairing sessions store only the new device's public JWK and an opaque wrap blob. Recovery uses Argon2id over the 12-word phrase. A minimal owner-only item API stores ciphertext so the second device can fetch and decrypt; live WS sync is Milestone 4.

**Tech Stack:** `@meownow/crypto`, IndexedDB, SimpleWebAuthn for the new device's passkey, Drizzle `pairing_sessions` / `items` / `users` vault columns.

**Spec tensions (do not paper over):**

- `pairing_sessions.user_id` is NOT NULL, but the new device creates the session before it is authenticated. Make `user_id` nullable until the enrolled device posts the wrap.
- WebCrypto `wrapKey` still needs an extractable subject. Persist a device-wrapped extractable copy; drop the live extractable handle after wrap.
- Identity private has no server column. Pairing carries a vault-wrapped copy in the opaque blob. Total-loss recovery rotates `identity_pub`.
- Untrusted server cannot see VaultKey, so recovery passkey enroll needs a phrase-derived verifier. Add `recovery_verifier_hash` (not in §1.4).
- Signup in §1.3 includes vault + phrase. M2 skipped that; M3 adds it on `/setup` after the passkey session exists.
- “Second device reads item” needs ciphertext at rest. M3 adds create/list only. Fan-out is M4.

**Done when:** Tests show device B, after fingerprint-confirmed pairing, decrypts an item encrypted on device A.

# Milestone 2 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship invite-only passkey auth so an 11th signup is impossible, the seeded admin can enroll a first device, and sessions are opaque cookies with server-side revocation.

**Architecture:** Vercel owns identity. Invite tokens are 32 random bytes; only `sha256(token)` is stored. Passkeys are discoverable WebAuthn credentials via `@simplewebauthn/server` + `/browser`. Seat claims use `FOR UPDATE SKIP LOCKED`, never `COUNT(*)`. Sessions are 256-bit opaque tokens hashed at rest. WebAuthn challenges live in an HMAC cookie so we do not add a table the spec does not define.

**Tech Stack:** Next.js 15 App Router, Drizzle + Neon Pool transactions, SimpleWebAuthn 13, Zod in `@meownow/protocol`, Vitest.

**Spec tensions (do not paper over):**

- Seeded admin has no passkey. First enroll is invite-less and gated by `ADMIN_ENROLL_SECRET` plus “this admin has zero devices.” After the first device exists, the route is closed.
- Signup in §1.3 includes vault + recovery phrase. Those are Milestone 3. M2 creates the user, passkey, session, and seat only.
- `SESSION_SECRET` is required to HMAC challenge cookies. It is not in the original env list; add it.
- Challenge state is a signed cookie, not a new table.

**Done when:** 11th signup returns zero seat rows / `seats_full`; denial paths for expired/revoked/redeemed invites, missing Origin, and non-admin invite creation are tested.

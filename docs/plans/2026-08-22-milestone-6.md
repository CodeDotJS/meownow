# Milestone 6 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Users without `can_upload` cannot write a byte to R2. Approved users upload chunked ciphertext through a Worker that verifies an EdDSA capability token.

**Architecture:** Vercel checks `can_upload` and quota, inserts a pending blob with a server-generated R2 key, and mints a 60s EdDSA JWT. The client PUTs chunks to the Worker. The Worker verifies the JWT, caps `Content-Length`, and streams to R2. Commit asks the Worker for the real size (`/stat`) because Vercel has no R2 credentials.

**Tech Stack:** WebCrypto Ed25519 JWT in `@meownow/protocol`, R2 binding on the Worker.

**Spec tensions:**

- Spec says Vercel `HeadObject`s R2. Vercel has no R2 key; the Worker holds the binding. Commit uses Worker `GET /stat` with a capability token.
- Env listed `CAPABILITY_TOKEN_PUBLIC_KEY` on the web app. The signer is Vercel, so the web app holds the private JWK; the Worker holds the public JWK.
- 60s TTL is kept by minting a fresh ticket per PUT rather than one token for a 100 MB upload.

**Done when:** A user with `can_upload=false` cannot mint a token, and a PUT to `/upload` without a valid token never calls R2 `put`.

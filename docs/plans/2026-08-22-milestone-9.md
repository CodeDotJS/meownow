# Milestone 9 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** CSP with per-request nonces and Trusted Types, token-bucket rate limits, nightly prune of expired rows / pending blobs / R2 orphans, and a runbook. Threat model matches the implementation.

**Architecture:** Next.js middleware mints a nonce and sets CSP. Send/auth limits live in HubDO storage (token bucket). Worker cron calls Vercel `/api/internal/prune` with a hub ticket; Vercel returns R2 keys; Worker deletes objects.

**Spec tensions:**

- `base-uri 'none'` as specified (Next.js examples use `'self'`).
- `style-src` cannot be nonce-only: React inline styles (TTL hairline, usage meter) need `'unsafe-inline'`.
- Bucket-wide R2 object expiry would delete **pinned** blobs. Cron is the expiry path; do not set a 7-day lifecycle on the whole bucket.
- Auth endpoints are on Vercel. The DO still holds the buckets; Vercel calls `POST /limit`.

**Done when:** Threat model documents CSP, rate limits, prune, and the pinning/lifecycle conflict. Tests prove denial (rate limit 429, prune deletes expired unpinned items and pending blobs older than 1 hour, CSP string contains the required directives).
